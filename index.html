이달의 상품 · 6개 반 공통

인원은 반마다 적용됩니다. 6개 반이 각각 따로 추첨하니 반끼리 상품을 나눠 갖지 않습니다.

규칙

저장은 이렇게 됩니다

① 버튼을 누르는 즉시 이 기기에 저장됩니다. 따로 저장할 필요가 없습니다.
② Supabase를 연결하면 마지막 조작 1.5초 뒤 자동으로 서버에 올라갑니다.
③ 파일 백업만 수동입니다. 기기를 옮기거나 통째로 보관할 때 씁니다.

헤더의 상태 배지에 마지막 저장 시각이 뜹니다. 배지를 누르면 지금 바로 동기화하고, Supabase를 연결하지 않았을 때는 백업 파일을 내려받습니다.

Supabase 동기화

로또 기록만 오갑니다. 학생 이름은 올라가지 않습니다.

테이블 만드는 SQL 
create table lotto_state (
  class_id   text primary key,
  data       jsonb not null,
  rev        bigint not null default 0,
  updated_at timestamptz default now()
);
alter table lotto_state enable row level security;
create policy anon_rw on lotto_state
  for all to anon using (true) with check (true);

시범과 초기화

수업에서 설명하실 때 예시로 채워 보여주고, 끝나면 0으로 되돌리는 용도입니다.

추첨 기록은 지워지지 않습니다. 명단도 그대로 남습니다.

파일 백업

이름까지 포함된 전체 백업입니다. 아직 Supabase를 연결하지 않았다면 이 파일이 유일한 백업이니, 수업이 끝날 때마다 내보내기를 눌러 두세요. 브라우저 캐시가 지워지면 복구할 방법이 없습니다.

다른 기기로 옮기려면 — 태블릿에서 내보내기 → 그 파일을 PC로 옮긴 뒤 PC에서 불러오기. 명단과 로또 기록이 통째로 넘어갑니다. Supabase를 연결하면 로또 기록은 자동으로 오가지만, 이름은 기기에만 남으므로 PC에서도 이름을 보고 싶다면 이 방법으로 한 번 옮겨 두면 됩니다.
